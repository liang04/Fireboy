# 十关合作内容改造与验证报告

本轮将十关改成各有侧重的合作任务，重点是角色交换、阶段推进和失误后的继续游玩。完整源码基于已核实的 `e5bf71ab886e283b2bfd9d42e7660bc326f34025`，在本地独立分支 `enrich/ten-stage-coop-2026-10-03` 修改；未推送、合并或部署。

支持并验证的运行环境为 **Godot 4.6.3 stable / Linux / 60 Hz**。交付是源码工程，可在 Godot 中打开 `project.godot` 后运行，不是 Windows 可执行文件。

## 十关具体变化

| 关卡 | 阶段和合作关系 | 可选内容或恢复路径 |
|---|---|---|
| 1 初识元素 | 浅池教学后，火娃走熔岩小桥守 A，水娃从桥下拉 B 接应 | 桥右侧安全落地与回桥台阶 |
| 2 哨台交接 | 一人传送上哨台守 A，另一人送箱压 B；守门者获释后共同渡池 | 哨台误落可从原传送门返回 |
| 3 分头行动 | 第一轮水娃守 C、火娃推进；第二轮火娃守 D、水娃开 E；最后庭院汇合 | 上下同时踩 V 才开放全宝石所需的合作宝库；普通通关可跳过宝库 |
| 4 时序接力 | 先由人守 A，队友从门后取箱回来替班；渡池后再做元素分路与末段双钥匙板 | 提前离板可回去继续；箱子无法替代末段高处钥匙板 |
| 5 中途接力 | 先送伙伴到安全中层，再交换供电职责，分段上升后顶层汇合 | 中层可停留整理，错过电梯可等下一班；中层小阳台收集 |
| 6 传送终局 | P1 先遣观察台守 A，地面伙伴拉 B 放行回路，最后经 P2 会合 | 两对明确编号的传送门；观察台小壁龛为可选红宝石支路 |
| 7 一路同行 | 两人护送同一个箱子上楼，推到 B 板后继续，最后守 D 接应 | 全关无液体；观景踏步、落回装载地面、错过电梯都可安全重来 |
| 8 遥供接力塔 | 左右轮流开启远端短升降段，到中继层后再次交换，末段双钥匙板供电登顶 | 中继层安全；分段采用保持开启的杠杆，避免一人长时间站板 |
| 9 总闸双路修复 | M 总闸成为中场事件；火娃在熔岩维修支路开 R，水娃在水中支路开 B，再到同一屋顶 | 屋顶入口分别受 R/B 控制，两人同乘左侧电梯不能跳过火路维修 |
| 10 合力投递 | 一人持续守箱子上不去的高桥 H，另一人推箱入井；井底 A 接收板开启左右归途 | 无条件 R1 传送门供误落角色返回；整井宽接收板使已投递箱子被误推到墙边后仍有效 |

第 10 关审查中发现并修复了真实软锁：原窄接收板允许玩家把已落井的箱子推离板并顶到墙边，角色无法站到箱子右侧推回。最终改为覆盖整口井的接收板，并新增真实输入回归：故意推到右墙后仍能全宝石完成。宽度是现有压力板的可选参数，默认仍为一格；没有改角色、箱子、平台或传送的运动规则。第 10 关扩大镜头留白，使高桥守板和井底投递目标能同时看清。

## 验证覆盖

- 原有控制、推箱、反馈、恢复、存档与 UI 套件保留并扩展为 229 项断言
- 十关加载、动作与机关联调冒烟
- 十关完整全宝石原始按键回放，精确比较帧数、宝石、死亡、箱复位和星级
- 15 个新增静态模型夹具，以及 13 个第 9/10 关几何断言
- 37 个有针对性的真实输入合作检查，覆盖不动一个角色、提前离板、单钥匙不能开门、错过电梯、平台断电后恢复、箱子替代尝试、错误元素维修、同乘左梯绕过尝试
- 哨台误落、接班中断、电梯错过和第 10 关箱子顶墙后的完整全宝石恢复路线
- 实际 Godot 图形模式回放与截图检查，图片来自运行画面，没有用编辑器摆放角色伪造通关

通关与合作检查在新关卡中只按下/松开真实 Input 动作，并读取正式游戏状态；不修改角色或箱子位置、速度，不注入宝石、时间、通道或完成状态。原有冒烟和组件回归会使用测试夹具或直接放置测试对象，其用途是组件联调，**不作为完整通关证据**。所有自动检查均隔离存档。

静态校验补充了两类原先不支持的运动：连续守板交接保留双方所在位置；木箱可以被真正的活动平台带到另一端，并检查运输通道净空。同时修复“下落跳跃穿过实心桥板”的静态误判。旧坏关卡自检仍全部运行，未对新关卡屏蔽致命错误。

仍保留三条静态警告：第 2 关悬在箱上方的红宝石不在静态站立面集合内，真实跳跃回放已取得；第 4、9 关箱子可被误推入液体，保留警告并由液体恢复测试覆盖。安全复位仍只针对液体和出界，加时 3 秒；普通投进井里的箱子不会复位，不能把它当撤销键。

## 复现和证据

在项目根目录运行：

```sh
python tools/run_checks.py --godot /path/to/godot
```

Godot 已在 PATH 中可省略参数。Windows 使用 `_console.exe` 路径，但本轮未在 Windows 验证。

只重放全宝石路线或重新保存针对性证据：

```sh
python tools/run_full_gem_routes.py --replay --output /tmp/full-gem-evidence.json
python tools/run_enrichment_checks.py --output-dir /tmp/enrichment-evidence
```

主要文件：

- `tools/enrichment/level_*.py` 与 `tools/gen_levels.py`：关卡源数据和静态校验
- `scripts/levels/levels.gd`：同步生成的正式运行数据
- `tools/full_gem_routes.json`、`tools/full_gem_route_replay.json`：路径和原始按键
- `tools/full_gem_route_evidence.json`：精确回放结果和源码 SHA-256
- `docs/evidence/enrichment/`：合作、恢复、升降和末关反例结果
- `docs/screenshots/enrichment/`：样板与最终实机渲染截图

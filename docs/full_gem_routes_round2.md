## 复现方法

项目根目录执行：

```sh
python tools/run_full_gem_routes.py --godot /path/to/godot --replay
```

启动器会先执行 Godot 导入，支持没有 `.godot` 缓存的新检出；已导入的项目可加 `--skip-import`。省略 `--replay` 会重跑路径控制器。也可只跑部分关卡或保留新证据：

```sh
python tools/run_full_gem_routes.py --godot /path/to/godot --replay --levels 1,8,10
python tools/run_full_gem_routes.py --godot /path/to/godot --replay --output /tmp/routes.json
```

相关文件：

- `tools/full_gem_routes.gd` / `.tscn`：使用正式 Level 场景的输入测试器
- `tools/full_gem_routes.json`：十关路线、目标格坐标及双人同步步骤
- `tools/full_gem_route_replay.json`：按键录制及精确预期结果
- `tools/full_gem_route_evidence.json`：引擎版本、源码 SHA-256、完成状态、帧数、游戏时间、宝石、死亡、复位、时限和星级
- `tools/run_full_gem_routes.py`：跨平台启动、存档隔离、导入及错误检查

按键录制采用 `frames`、`mask` 游程编码。位 0–7 依次为火娃左、右、跳、交互，水娃左、右、跳、交互；一个 mask 保持指定物理帧数。独立回放直接执行录制按键，不读取位置来决定下一步。

回放断言：真实通关、全宝石、精确完成帧数、死亡/复位次数、各色宝石实收数/总数及三星结果。脚本错误、缺少结果、关卡不全、源码在运行期间改变或任何断言失败，都会返回非零退出码。失败但已产出的结果也会写入报告。

## 证据边界与反例测试

测试前只选择一个新关卡，并设置 `GameState.suppress_recording`。同时将 HOME、APPDATA 和 XDG 数据/配置/缓存目录隔离到临时目录。

开始计时后，测试器只读取正式游戏状态和按下/松开八个输入动作，不修改位置、速度、生命、碰撞、宝石数量、时间、机关通道或完成状态，也不主动发送任何游戏事件。传送门移动、平台载人、杠杆、压力板、捡宝石和出口判定均由正式游戏代码执行，关卡几何没有替换。箱子恢复组件正常启用，但成功路线均未触发恢复。

最后一关结果冻结并释放场景后，才停止剩余音效并等待音频线程清理；这不会改变任何记录的完成帧数、计时或成绩。

反例验证：将第 1 关整段 486 帧替换为空输入，得到红 0/3、蓝 0/3、未通关，并以退出码 1 失败，原因为 `input tape exhausted before completion`。因此“场景没有崩溃”不会被误认成“通关成功”。另在不含 `.godot` 的临时完整项目副本上，确认自动导入后十关回放均通过。

精确坐标、跳跃/游泳/搭乘步骤与同步点见路线 JSON：

1. 火娃取岩浆底宝石，水娃跳过；水娃取水底宝石，火娃跳过；分别爬台阶取宝石进门
2. 两人经出生点左侧传送门取高台宝石；火娃推箱压 A；同乘平台渡毒池，取地面宝石并拉 B，分别处理水池与终点台阶
3. 火娃走上层台阶、取岩浆宝石并拉 A；水娃取水底宝石后保持 C；火娃通过上层门拉 E，再各进出口
4. 箱子压 A、平台渡池；水娃保持 B，火娃取岩浆宝石并拉 C；水娃从左侧登上台阶，两人同时压住 K 双板后取余下宝石出门
5. 火娃取岩浆宝石，水娃压板供左梯；火娃登顶打开右梯，暂不进出口；水娃取水底宝石并坐右梯取顶部宝石，最后两人再进门
6. 箱子压 A，分头处理水池，共乘毒池平台；分头处理岩浆、打开 B；水娃先取低处凹槽宝石，再分别通过正式传送门进上层出口
7. 拉 A、箱子压 B，分别取地面及台上宝石；乘梯后火娃在高块上压 D，水娃通过门后，火娃再走向自己的出口
8. 火娃取所有地面红宝石并给水娃电梯供电；水娃登塔后，火娃先登上尚未通电的左梯，水娃再拉 EA；各取顶部宝石进门
9. 箱子压 A、平台渡毒池、取地面宝石、拉 M，再搭左侧高塔电梯；跳上高岛取各色宝石后进门
10. 水娃先取桥顶和地面蓝宝石，再从箱子右侧将它推落到 A，角色留在上层；火娃取两颗红宝石后，两人各进出口

## 时限处理与仍待验证的内容

历史 `BASE_TIMES × 1.20` 不是全宝石基准：普通最快与最多宝石可能来自不同局，第 4、10 关还含估值。缺少某条全宝石记录，本身不能证明三星不可达。

本轮已经用真实输入证明十关现有时限均可达；但这不是最优解、真人最快记录，也不衡量初见解谜难度、双人沟通负担、键盘操作或实体手柄体验。

因此保留全部原时限，明确其仍是暂定的真人难度目标；不按一条机器人路线收紧门槛，不提升 `RATING_VERSION`。后续真人平衡应记录同一局完整全宝石成绩，并明确目标玩家水平。Windows 实机与实体手柄仍需另行验证。

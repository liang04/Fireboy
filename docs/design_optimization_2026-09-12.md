# 设计向优化实施记录（2026-09-12）

> 前两轮优化（`optimization_analysis.md` / `optimization_implemented.md`）全部集中在
> **工程层**：崩溃修复、性能、类型安全、音效手柄暂停。本轮是第一次**游戏设计层**干预。
> 诊断结论与理由见 §1，落地清单见 §2。

---

## 1. 本轮要解决的问题

工程地基极好（channel 解耦 / 可达性校验器 / 运动能力探针 / 程序化美术），
但**核心循环被「过度容错」短路了**：

> 死亡 1 秒重生 + 机关状态保留 + 已拾宝石保留 = **没有任何需要重新决策的失败状态**。
> 玩家最优策略恒为「往前冲，死了再来」，解谜从「思考」退化成「遍历」。

具体拆成三个缺口，外加两处节奏问题：

| # | 缺口 | 证据 |
|---|---|---|
| 1 | 失败零代价 → 张力消失 | `player.gd::respawn()` 只重置位置；`level.gd` 死亡仅 `_deaths += 1`，失误不进任何评价 |
| 2 | 宝石是装饰性资源 | 宝石全部「顺路」或「池底（有免疫就能拿）」，不制造取舍；收集率不解锁任何东西 |
| 3 | 机关因果不可见 | `moving_platform.gd` 通电/断电**外观完全一致**；HUD 不显示死因（`die(cause)` 有数据没人用） |
| 4 | 末段三连高负荷 | 认知负荷 3-4 关、6-7-8 关连续高，无缓冲 |
| 5 | 第 7 关纯等待 | 火娃必须一直踩板，等待对岸电梯往返期间无事可做 |

## 2. 落地清单

### P0-A 星级评价（`level.gd` / `hud.gd` / `game_state.gd` / `main_menu.gd`）

**设计解法**：把「惩罚玩家」改成「阻碍完美」。

| | 规则 |
|---|---|
| 1 星 | 通关保底 |
| 2 星 | 命中「全宝石 / 少失误 / 快通关」三项中的 1 项 |
| 3 星 | 命中其中 ≥2 项 |

- **星级不锁任何进度** —— 这是「宽容 vs 张力」的解法：失败不惩罚你通关，只惩罚你完美。
  支柱 3「失误要便宜」和「谜题要有张力」因此不再互相打架。
- 阈值 `DEATH_TARGET = 3`、`TIME_TARGET = 180.0`，**均为 [PLACEHOLDER]**，
  假设与验证路径写在 `level.gd` 常量区注释里。
- 存档取历史最高星（与其它纪录语义一致）；菜单每关按钮前置显示 `★★☆`，
  一眼看出哪关还没满星。

### P0-B 死因反馈（`level.gd` / `hud.gd`）

死亡时弹归因提示，按液体上色：
- `水娃碰岩浆会融化 —— 那是火娃的路`（岩浆橙）
- `火娃碰水潭会被浇灭 —— 那是水娃的路`（水潭蓝）
- `X被毒液腐蚀 —— 毒液谁都不能碰`（毒液绿）

**rationale**：`die(cause)` 一直在传死因，只是没人接。第一次死在岩浆上的玩家
如果不知道是岩浆，只会以为游戏在乱杀他——而「谁怕什么」正是元素相克教学的地基。

### P0-C 供电 / 激活状态可视化（`moving_platform.gd` / `door.gd` / `tex.gd`）

这是本轮**投入产出比最高**的一条。

- 受 channel 控制的平台：下沿一条能量带，通电亮黄并呼吸，**断电时平台本体一起压暗**。
  否则电梯停在半空时，玩家分不清是「到站」还是「断电」。
- 门顶加一盏通电指示灯，收到信号亮起、与门一起下沉。
- 新增 `Tex.C_POWER_ON` / `C_POWER_OFF`；通电色**刻意复用压力板激活的暖黄**，
  让「板亮了 = 有电了」成为统一语言。

### P1-F 总闸共时反馈（`level.gd` / `hud.gd` / `sound.gd`）

- `level.gd` 装配后数节点树统计每个 channel 的**扇出**（受控物数量），不读关卡数据，
  所以加关卡永远不用维护这张表。
- 某 channel 激活且扇出 ≥2 时，触发一次强调：`power` 音效（比 `mechanism` 更长、
  跨度更大的上行扫频）+ 全屏泛暖光。带 1.2s 冷却，防止在板上反复起跳刷屏。
- **rationale**：第 8 关的设计价值是「channel 解耦的证明」，但玩家不关心架构，
  只关心「这一下拉得爽」。

### P1-E 第 7 关消 dead time（`tools/gen_levels.py`）

- 两台电梯单程速度 130 → 165（384px/165 ≈ 2.3s），压缩纯等待。
- 火区远端 x22 补一颗红宝石，给追求全收集的玩家一个可选的并行目标。
- **不改**「火娃必须一直踩板」这个设定 —— 那是第 7 关「遥供」的灵魂。

### P2-G 菜单进度可视化

随 P0-A 一并完成：`main_menu.gd::_badge()` 前置星级。

## 3. 验证结果

```
python tools/gen_levels.py
  → 9 个自检夹具全命中；8 关静态校验全通过
  → 第 7 关对象 10 → 11（新增宝石）；解法仍为「火娃按住 EB」，与设计意图一致

godot --headless --path . -- --smoke
  → levels=8，errors=0；动作能力实测值不变（跳 107 / 远 199 / 制 5 / 浮 146 px）
  → 第 7 关 gems=3/4 red（新增红宝石已生效）

godot --headless --path . res://tools/regression.tscn
  → 31 项断言全过，errors=0（原 24 项 + 新增 7 项：
     死因归因、3 星、1 星、2 星、高扇出触发、平台通电前/后状态）
```

## 4. 未实施项（需要专门设计，不在本轮）

| 项 | 为什么没做 |
|---|---|
| **P1-D 插入呼吸关** | 涉及新增 / 重排关卡，属于「paper prototype 先于实现」的范畴。当前曲线 3-4 关、6-7-8 关两段连续高负荷确需缓冲，但具体插在哪一关、用什么低认知机制，应先出纸面设计再改生成器 |
| **P2-H 单人兜底模式** | 本地双人是原版灵魂，做成「对称单人」会废掉整个设计。若要做，方向是「轮流操作」或「AI 辅助」，且要单独评估它与双人谜题的可解性冲突 |

## 5. 待人工验证（自动化测不到的部分）

| 项 | 假设 | 验证路径 |
|---|---|---|
| 星级阈值 | `DEATH_TARGET=3` / `TIME_TARGET=180s` 合理 | 录一次双人首通，统计每关用时与失误分布后回填 |
| 供电可视化的辨识度 | 断电压暗 + 能量带变暗足够看懂 | 让从没玩过的人看第 5 关电梯断电那一刻，问「它是在停还是坏了」 |
| 死因提示的措辞与时机 | 1.6s 冷却不会吞掉关键教学 | 观察首次死亡是否都看到了归因 |
| 第 7 关新节奏 | 2.3s 单程不再烦躁 | 计时统计单次等待时长 |
| 总闸闪屏强度 | 0.16 alpha 不刺眼 | 真人试玩看第 8 关拉杆瞬间 |

> 所有阈值与强度均为纸面推演值，未经真人试玩，等实测数据回填。
